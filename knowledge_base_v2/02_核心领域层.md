# V2 知识库 - 02 - 核心领域层 (The Core Domain)

**架构定位**: 如果说“引擎层”是心脏，那么本层就是整个 `ModernUI` 框架的“大脑”和“骨架”。它定义了 UI 世界的核心概念和运转规则，负责将引擎层发出的“遍历”指令，转化为对UI组件具体的“测量、布局、绘制”操作，并处理来自用户的输入事件。

**核心模块**: `icyllis.modernui.view`, `icyllis.modernui.fragment`, `icyllis.modernui.app`

## 核心结论 (审计 V2 修正)

-   **领域核心的扩展**: V1 版将领域核心局限于 `view` 包，这是一个认知盲区。`TestFragment.java` 和 `ModernUI.java` 揭示了 `core` 模块内还包含了一套完整的 **`Activity`/`Fragment` 架构**。因此，V2 版的领域核心被扩展为 **View 系统 + Fragment 系统**。
    -   **View 系统**: 底层的 UI 原子和容器，负责渲染和事件分发。
    -   **Fragment 系统**: 更高阶的 UI 组织和控制器，负责 UI 模块的生命周期管理和复用。
-   **`Context` 的来源与实现**: V1 版对此是模糊的。V2 版明确：`ModernUI` 类继承自 `Activity`，而 `Activity` 继承自 `Context`，因此 **`ModernUI` 实例自身就是根 `Context`**。它在启动过程中创建并持有 `WindowManager` 等核心服务，并通过 `onAttach` 回调将自身注入到 `Fragment` 中，解决了“`Context` 从何而来”的关键问题。

## 关键组件分析

### 1. `app.Activity` & `ModernUI.java` - 应用顶层与 `Context` 提供者

-   **角色**: `Activity` 是一个抽象类，它代表了一个应用窗口的顶层容器，并承担了作为 `Context` 实现者的职责。`ModernUI` 类是 `Activity` 的一个具体实现，同时也是整个应用的引导程序。
-   **生命周期 (`LifecycleOwner`)**: `ModernUI` 实现了 `LifecycleOwner` 接口，通过一个 `LifecycleRegistry` 对象，管理着整个应用的生命周期状态（`ON_CREATE`, `ON_START`, `ON_STOP` 等）。
-   **服务提供**: 作为 `Context`，`ModernUI` 实例在 `run()` 方法中创建了 `WindowGroup` (即 `WindowManager` 的实现)，并通过 `getWindowManager()` 方法向上层提供服务。其他服务也以类似方式被管理。

### 2. `fragment.Fragment` - 可复用的 UI 控制器

-   **角色**: `Fragment` 是一个独立的、拥有自己生命周期的 UI 控制器。它将一部分 UI 的视图（`View`）和逻辑（代码）封装在一起，以实现模块化和复用。
-   **核心生命周期**: 
    -   `onAttach(Context context)`: `Fragment` 被附加到 `Activity` 时调用，此时 `Context` 被注入。
    -   `onCreate(DataSet savedInstanceState)`: 进行非视图相关的初始化。
    -   `onCreateView(...)`: **必须实现此方法**，在其中创建并返回该 `Fragment` 所管理的 `View` 树。
    -   `onDestroy()`: 销毁。
-   **`FragmentManager` & `FragmentTransaction`**: `Fragment` 的添加、替换、移除等操作不是直接进行的，而是通过 `FragmentManager` 创建一个 `FragmentTransaction`（事务），将一系列操作加入事务，最后通过 `commit()` 来异步执行。这套机制确保了 `Fragment` 状态的稳定和可预测性，并支持返回栈（Back Stack）功能。

### 3. `view.View`, `view.ViewGroup`, `view.ViewRoot` - UI 渲染与事件核心

这部分内容与 V1 版的分析基本一致，它们构成了 `Fragment` 所管理的 `View` 树的基础。

-   **`View`**: UI 原子，负责 `onMeasure`/`onLayout`/`onDraw` 的最终执行。
-   **`ViewGroup`**: UI 容器，负责组织子 `View` 的三大流程，并通过 `onInterceptTouchEvent` 协调事件分发。
-   **`ViewRoot`**: 根节点协调者，连接**引擎层**和 `View` 树，驱动 `performTraversal`，是 `View` 世界与外部的桥梁。

## V2 领域层工作流

1.  **启动**: `ModernUI.main()` -> `new ModernUI().run(new TestFragment())`。
2.  **`Activity` 创建**: `ModernUI` 实例被创建，它自身就是一个 `Context` 和 `LifecycleOwner`。
3.  **`Fragment` 附加**: `run()` 方法内部，`FragmentController` 会将 `TestFragment` 附加到 `ModernUI` 这个 `Host` 上。
4.  **`Context` 注入**: 在附加过程中，`TestFragment.onAttach(context)` 被调用，`ModernUI` 实例作为 `context` 被传入。
5.  **`View` 创建**: 随后，`TestFragment.onCreateView()` 被调用。`TestFragment` 内部使用 `getContext()` 方法获取之前注入的 `ModernUI` 实例，并用它来创建 `View`（如 `new ScrollView(getContext())`）。
6.  **`View` 树上屏**: `Fragment` 创建的 `View` 最终被添加到 `ViewRoot` 所管理的 `DecorView` 上，最终显示在屏幕上。
