# V2 知识库 - 03 - 服务表现层 (The Service & Presentation)

**架构定位**: 本层是整个 `ModernUI` 框架的“工具箱”、“素材库”和“预制件集合”。它不包含框架的核心驱动逻辑或领域规则，而是为“核心领域层” (`View` 和 `Fragment`) 提供所有必要的服务与具体实现，使其能够完成最终的渲染和交互。

**核心模块**: `graphics`, `resources`, `widget`, `util` 等。

## 核心结论 (审计 V2 修正)

-   **服务角色的确认**: 本层作为“被动服务”的角色定位在 V1 版中是正确的，V2 版对此进行确认。这些模块等待“核心领域层” (`view`, `fragment`) 的调用，为其提供数据（`resources`）、能力（`graphics`）和具体实现（`widget`）。
-   **与核心的关联更清晰**: 结合 `ModernUI.java` 的分析，我们现在能更清晰地看到这些服务是如何被创建和注入的。
    -   `Resources`: 在 `ModernUI` 的构造函数中，通过 `ResourcesBuilder` 被创建，成为 `Activity` 的核心成员。
    -   `Canvas`: 在 `ViewRootImpl` 的 `beginDrawLocked` 方法中，由 `arc3d` 的 `GraniteSurface` 创建，并包装成 `ArcCanvas` 后，传递给 `View` 的 `draw` 方法。

## 关键模块分析

### 1. `graphics` - 渲染服务

-   **角色**: 提供一套 2D 绘图的**能力 API**，充当 `View` 系统的“画笔” (`Paint`) 和“画布” (`Canvas`)。
-   **被动调用**: `Canvas` 和 `Paint` 对象自身不会主动执行任何操作。它们被 `View.onDraw()` 和 `Drawable.draw()` 等方法创建和使用，将其中的绘图指令（`drawRect`, `drawText` 等）记录到 `arc3d` 的 `Recording` 对象中。这个 `Recording` 对象随后被传递到**渲染线程**，由 GPU 最终执行。
-   **`drawable` 子包**: 提供了一系列可复用的“可绘制对象” (`Drawable`)。这是对 `graphics` API 的一层更高阶的封装，将绘图逻辑封装成可管理的、具备状态的对象。`StateListDrawable` 是其中的关键，它响应 `View` 的状态变化来切换自身的视觉呈现，是连接 `View` 状态和 `graphics` 绘制的桥梁。

### 2. `resources` - 资源与主题服务

-   **角色**: 负责加载和管理所有非代码资源，是 `View` 系统外观和内容的“素材库”。
-   **创建与注入**: `Resources` 对象在 `ModernUI` 的构造函数中被创建，并作为 `Activity` 的一部分而存在。`Fragment` 和 `View` 通过 `getContext().getResources()` 调用链，最终访问到这个由 `ModernUI` 实例持有的 `Resources` 对象。
-   **工作模式**: 这是一个**编译型**资源系统。
    1.  **编译期**: `ResourcesBuilder` 等工具将 XML 文件（布局、Drawable、样式等）和图片编译成高效的二进制格式。
    2.  **运行时**: `AssetManager` 加载这些二进制包。`Resources` 类作为统一入口，提供 `getDrawable()`, `getColor()` 等方法。
-   **`Theme` 与 `TypedArray`**: 这是资源服务的核心价值所在。`TypedArray` 在 `View` 的构造过程中，通过 `Context.getTheme()` 获取当前主题，并解析 XML 属性，处理样式继承和覆盖，最终将计算出的值提供给 `View`。

### 3. `widget` - 核心领域层的具体实现

-   **角色**: 基于 `View` 和 `ViewGroup` 这两个核心抽象，提供的一系列可以直接使用的“预制件”或“实现案例”。
-   **分类**: 
    -   **布局容器 (`ViewGroup` 实现)**: `LinearLayout`, `FrameLayout`, `RelativeLayout` 等。它们各自实现了不同的 `onMeasure` 和 `onLayout` 逻辑，提供了不同的子视图布局策略。
    -   **基础组件 (`View` 实现)**: `TextView`, `ImageView`, `ProgressBar`, `Button` 等。它们各自实现了不同的 `onDraw` 和 `onTouchEvent` 逻辑，用于显示特定内容和处理特定交互。
-   **学习价值**: `widget` 包是理解 `View` 和 `ViewGroup` 工作原理的最佳实践参考。例如，通过阅读 `LinearLayout`，可以清晰地看到 `onMeasure` 中处理 `layout_weight` 的完整流程。

### 4. `util` - 通用基础设施 (Infrastructure)

-   **角色**: 一个独立的、与UI框架无耦合的底层工具包，提供通用的数据结构和辅助功能。
-   **关键组件**: 
    -   `SparseArray`: 内存优化的 `HashMap<Integer, E>` 替代品。
    -   `Pools`: 通用的对象池实现，用于复用高频创建和销毁的对象。
    -   `Log`: 对 SLF4J 的封装，统一日志接口。
-   **架构地位**: 它不属于 UI 框架的核心三层（引擎、领域、服务）中的任何一层，而是作为最底层的**地基**，被所有上层按需使用。
