# V2 知识库 - 01 - 引擎驱动层 (The Engine)

**架构定位**: 本层是整个 `ModernUI` 框架的“心跳”和“神经中枢”，是所有UI更新、事件处理和动画执行的“第一推动力”。它独立于任何具体的UI组件，为上层提供了一个统一的、与硬件刷新率同步的调度模型。

**核心模块**: `icyllis.modernui.core`, `icyllis.modernui.ModernUI`

## 核心结论 (审计 V2 修正)

-   **双线程模型是核心**: V1 版将引擎简化为单线程模型，这是一个关键偏差。`ModernUI.java` 的 `run()` 和 `runRender()` 方法清晰地揭示了框架的引擎是一个**双线程模型**：
    -   **UI 线程 (`Main-Thread`)**: 负责所有非渲染的逻辑，包括 `View` 的测量/布局、事件处理、动画状态更新以及 `Fragment` 的生命周期管理。它运行着 `Looper.getMainLooper()`。
    -   **渲染线程 (`Render-Thread`)**: 专门负责与 `arc3d` 和 `LWJGL` 交互，执行 OpenGL 指令。它拥有自己独立的 `Looper` (`mRenderLooper`)。
-   **线程同步机制**: UI 线程和渲染线程并非完全独立，它们在 `ViewRootImpl.endDrawLocked()` 处进行精确同步。UI 线程将绘制指令（`Recording`）提交给渲染线程后会 `wait()`，等待渲染线程完成真正的 GPU 操作后将其唤醒。这个机制确保了数据在两线程间的安全传递，并避免了 UI 线程因等待 GPU 而卡顿。
-   **`Choreographer` 角色不变**: `Choreographer` 依然是驱动 UI 线程的“节拍器”，但它的作用域被更精确地限定在 UI 线程内部，负责调度 `performTraversal`。

## 关键组件与流程

### 1. 引导程序 `ModernUI.java`

-   **职责**: `ModernUI` 类是整个框架的引导程序和总协调者。
-   **`run()` 方法**: 这是应用启动的入口。它负责：
    1.  初始化主线程 `Looper` (`Looper.prepareMainLooper()`)。
    2.  创建并启动一个名为 `Render-Thread` 的新线程，该线程执行 `runRender()` 方法。
    3.  创建 `ViewRoot` 和 `DecorView`（`WindowGroup`），搭建起 `View` 树的顶层结构。
    4.  通过 `Looper.loop()` 启动主线程的消息循环。
-   **`runRender()` 方法**: 这是渲染线程的入口。它负责：
    1.  初始化 OpenGL 上下文 (`Core.initOpenGL()`)。
    2.  创建属于渲染线程自己的 `Looper` 和 `Handler`。
    3.  启动渲染线程的消息循环。

### 2. 双线程消息循环

-   **UI 线程循环**: 由 `Looper.getMainLooper()` 驱动，通过 `Choreographer` 接收 V-Sync 信号，并在每个“遍历”时刻执行 `ViewRoot.performTraversal()`。
-   **渲染线程循环**: 由 `mRenderLooper` 驱动，它不响应 V-Sync，而是被动地等待来自 UI 线程的 `Handler` 消息，以执行具体的渲染任务。

### 3. 核心同步流程 `ViewRootImpl.endDrawLocked()`

这是理解双线程模型的关键，它发生在 `performTraversal` 的绘制阶段末尾：

1.  **[UI 线程]**: 在 `View` 树的 `draw()` 调用完成后，`arc3d` 引擎生成了一个包含所有绘图指令的 `Recording` 对象。
2.  **[UI 线程]**: `endDrawLocked` 将这个 `Recording` 对象存入 `mLastFrameTask`，然后通过 `mRenderHandler.post(this::render)` 向**渲染线程**发送一个执行 `render()` 方法的消息。
3.  **[UI 线程]**: 发送消息后，UI 线程立即在 `mRenderLock` 对象上调用 `wait()`，进入等待状态，释放 CPU，让其他任务可以执行。
4.  **[渲染线程]**: 其 `Looper` 从消息队列中取出 `render()` 任务并执行。
5.  **[渲染线程]**: `render()` 方法从 `mLastFrameTask` 中取出 `Recording` 对象，将其提交给 `arc3d` 的 `ImmediateContext`，最终转化为 OpenGL 指令被 GPU 执行。同时，它调用 `mWindow.swapBuffers()` 来交换显示缓冲区。
6.  **[渲染线程]**: 渲染完成后，在 `mRenderLock` 对象上调用 `notifyAll()`，唤醒正在等待的 UI 线程。
7.  **[UI 线程]**: 从 `wait()` 中被唤醒，完成本次 `traversal`，并准备接收 `Choreographer` 的下一次节拍信号。
